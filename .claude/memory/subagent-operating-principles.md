서브에이전트와 스킬 사용에 대해 사용자와 합의한 운영 기준.

1. **작업 규모 3단 구분**: 대규모 프로젝트 → GSD 파이프라인 / 중간 규모 일회성 구현 → `subagent-driven-development` 스킬 / 소소한 수정 → 직접 수행 (에이전트 없이).
2. **개입 기준**: "단계"가 아니라 **비가역성·모호성** 기준. 되돌리기 쉬운 결정은 실행 중 자율 판단, 비가역적·외부 부수효과·모호한 스펙은 중단 후 질문. 모호한 작업은 초반 1~2작업 후 방향 확인 1회, 완료 후 검수는 항상.
3. **모델 혼용 기준**: "단순하면 저모델"이 아니라 **"검증이 싸면 저모델"**. 테스트·형식 검증으로 오답이 즉시 드러나는 작업만 Haiku 등 저모델에 위임. 틀려도 티가 안 나는 작업(설계·검증·보안 판단)은 상위 모델.
4. **토큰 원칙**: 메인 컨텍스트에는 결론만, 과정은 서브에이전트에 격리, 탐색은 Explore 에이전트.

**Why:** 자동화 극대화가 목표지만 "개입 최소화" 자체가 목표가 아니라 "개입당 가치 최대화"가 목표. 저모델 오류는 리뷰(고정비)로 잡되, 검증이 비싼 작업은 처음부터 상위 모델이 총비용이 더 쌈.

**How to apply:** 구현 계획 실행 요청 시 규모를 먼저 판단해 3단 중 선택. 스킬은 description 기반 자동 판단으로 호출. T0 강제 규칙 추가는 보류 상태 — 자동 판단이 미덥지 않으면 그때 CLAUDE.md에 추가 (사용자 결정 2026-08-24). 관련: [[check-existing-conventions-first]]
