"이런 게 있으면 나중에 좋을 것 같다"는 이유로 폴더 구조·gitignore 규칙·스킬 설치·설정을 미리 만들지 않는다.
**지금 그걸 쓸 구체적인 대상(프로젝트·phase·작업)이 있을 때 그 자리에서 만든다.**

**Why**: GSD가 `ROADMAP.md`/`config.json`/`phases/`를 미리 만들지 않는 것과 같은 이유 —
빈 껍데기를 미리 두면 나중에 실제로 필요해졌을 때의 온디맨드 초기화와 충돌하거나 무의미해진다.
이건 파일 스캐폴딩뿐 아니라 **스킬 설치**에도 그대로 적용된다 — 스킬도 매 세션 스킬 목록에 로드되는
비용이 있어서(루트 `CLAUDE.md`의 T0 예산 논리와 동일), 쓸 사람이 없는 스킬을 미리 깔아두는 것도 같은 실수다.

**실제 사례 (2026-08-26)**: osm-test 검증 스크린샷 정리 과정에서 "검증용 캡처를 `.planning/verification/`에
보관하는 관행 + 루트 gitignore + 템플릿 반영"까지 구축했다가, 사용자가 "애초에 저장할 필요가 있냐"고
되물어서 전부 되돌렸다 — 재사용 가치 낮은 작업 로그는 삭제가 맞았다([[generalizable-convention-placement]]
참고). 이어서 시각적 회귀 테스트용 Playwright 스킬(`playwright-best-practices`, 75.7K 설치)을 찾아 설치를
제안했는데, 이것도 같은 이유로 보류했다 — 이 저장소의 어느 프로젝트도 아직 회귀 테스트가 필요한 성숙도에
이르지 않았다.

**How to apply**: "이거 나중에 필요할 수도 있으니 미리 준비해두자"는 제안이 내 쪽에서 나오려는 순간,
멈추고 "지금 이걸 쓸 구체적 대상이 있는가"를 먼저 묻는다. 없으면 만들지 않고, 필요해지는 시점에
(재검색·재설치 비용이 대개 낮으므로) 그때 만든다.
