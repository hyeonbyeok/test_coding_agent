프로젝트 하나에서 규칙을 고치면서 "이거 다른 프로젝트 만들 때도 똑같이 필요한 거 아닌가"라는 질문이 나오면, 아래 기준으로 판단한다.

**판단**: 그 규칙이 프로젝트의 도메인 사실(용어·제약·기술 결정)이 아니라 **앞으로 어떤 프로젝트를 만들든 반복될 작업 관행**이면 일반화 대상이다.

**어디에 반영하는지 (비용 순)**:
1. 강제(enforcement)가 필요하면 **루트 `.gitignore`** — 전체 하위 프로젝트에 자동 적용, 세션 컨텍스트 비용 0
2. 새 프로젝트가 인지해야 하면 **`.claude/templates/subproject-CLAUDE.md`** — 새 프로젝트 생성 시 복사되어 T2로 로드(그 프로젝트를 열 때만), 비용 낮음
3. 루트 `CLAUDE.md`(T0)에는 넣지 않는다 — 매 세션 전체에 로드되고, 이미 자체 예산(60줄)을 넘긴 상태([[root-claude-budget-overage]] 참고 필요 시 확인)

**전제**: 이 판단은 "저장·강제할 무언가가 실제로 있을 때"만 적용한다. 저장할 필요 자체가 없다면(예: 검증용 스크린샷 — 확인 후 삭제가 맞았다, [[defer-infrastructure-until-actual-need]] 참고) gitignore·템플릿 어느 쪽에도 넣지 않는다. "일반화 대상인가"를 묻기 전에 "애초에 지속시켜야 하는가"부터 확인한다.

**Why**: 하위 프로젝트 CLAUDE.md만 고치면 그 프로젝트에서만 적용되고 다음 신규 프로젝트에서 재현되지 않는다 — 사용자가 직접 지적함.
**How to apply**: 하위 프로젝트에서 폴더 규칙·gitignore 패턴·문서 배치 규칙을 새로 만들기 **전에**, ① 이게 애초에 저장할 필요가 있는 것인가 ② 있다면 이 프로젝트만의 사정인지 반복될 관행인지, 순서대로 확인한다.
